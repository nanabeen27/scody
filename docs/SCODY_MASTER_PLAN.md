# SCODY MASTER PLAN

제품 방향과 확정 정책, 현재 상태, 남은 작업만 담는다.
진행 기록은 `docs/archive/SCODY_WORKLOG_2026-07.md`, 품질 점수는 `docs/PRODUCT_QUALITY_SCORE.md`.

새 결정이 생기면 기존 정책을 덮어쓰지 말고 아래 `결정 대기` 또는 `결정 기록`에 근거와 함께 남긴다.

---

## 1. 제품

스코디는 고등학생이 국어 문제를 풀고, 결과와 취약 영역을 바탕으로 다음 학습을 이어 가는 학습 플랫폼이다.

한 학생 계정에서 세 가지 형태를 지원한다.

1. 학생이 직접 결제하는 개인 학습
2. 학부모가 결제하고 관리하는 학습
3. 학원이 비용을 부담하고 재원생에게 과제를 배정하는 학원 연계 학습

핵심 가치

- 학생은 오늘 무엇을 해야 하는지 바로 안다.
- 학부모는 자녀가 실제로 공부했는지, 어디가 약한지 쉽게 확인한다.
- 학원은 적은 조작으로 배정하고 결과를 본다.
- 개인 학습과 학원 학습은 함께 제공하되 출처와 권한이 섞이지 않는다.
- 학원이 바뀌거나 번호가 변경돼도 학생 기록은 유지된다.

## 2. 변경할 수 없는 정책

- **사용자 역할**: 학생 / 학부모 / 학원 구성원(원장·선생님) / 총괄관리자. 한 계정이 여러 역할을 가질 수 있고, 로그인 후 공간을 전환한다.
- **결제 주체**: 학생 본인, 학부모, 학원.
- **이용권 병존**: 개인 이용권과 학원 이용권을 한 학생이 동시에 가질 수 있다.
- **계정 식별자**: 영구 `user_id`. 학습 기록·구독·소속·자녀 연결은 전화번호가 아닌 `user_id`에 붙는다. 전화번호는 인증·복구·초대 확인·연락처 변경·알림에만 쓴다.
- **로그인 방법 두 가지**: 로그인 화면은 `카카오로 로그인` + `휴대폰 번호로 로그인`만 둔다. 휴대폰은 번호 확인 → 인증번호 두 단계다. 회원가입도 같은 두 가지(`카카오로 가입하기`·`휴대폰 번호로 가입하기`)로 시작한다(D-020).
- **서비스 한 줄 소개**: 소개 페이지 첫 문장은 `Scody는 학생의 학습을 가장 효율적으로 만드는 학습 플랫폼입니다.`로 고정한다(D-021).
- **학생 기록의 지속성**: 학원 연결이 끝나도 계정과 과거 기록은 유지한다. 재풀이 요청은 기존 기록을 지우지 않는다.
- **데이터 공개 범위**
  - 학원은 자기 학원이 배정한 학습과 그 결과만 본다. 학생의 개인 학습 상세와 개인 학습 오답노트는 학원에 공개하지 않는다.
  - 학부모는 연결된 자녀의 개인·학원 학습을 모두 본다(오답노트 메모·별표 포함).
  - 학원 콘텐츠는 그 학원과 운영자만 배정할 수 있다. 다른 학원 콘텐츠는 보이지 않는다.
- **상위 정보 구조**: 아래 4절 그대로.

변경이 필요하면 구현하지 말고 `결정 대기`에 쟁점·선택지·권장안·보안 영향·마이그레이션 영향을 적는다.

## 3. 계정·초대

- 학원이 학생을 초대하면 기존 계정에는 소속만 추가하고 새 계정을 만들지 않는다. 개인 구독은 그대로 유지한다.
- 학원이 학부모를 초대하면 자녀 관계를 확인하고 연결을 승인한다.
- 원장이 선생님을 초대하면 소속과 역할을 승인한 뒤 담당 반을 배정한다. 원장은 선생님을 추가·제외할 수 있고, 제외된 선생님의 담당 반은 미배정으로 표시한다.

학원 권한

- 원장: 학원 전체 관리, 선생님 초대·추가·제외, 반·학생 관리, 전체 결과, 요금제·이용 인원
- 선생님: 담당 반과 학생, 학습 배정, 제출·결과, 담당 학생의 학부모 리포트

## 4. 정보 구조

### 웹 소개 페이지 `/introduce` — 로그인 전 첫 화면

- 상단 바: `Scody` 워드마크(좌) · `로그인`·`회원가입`(우). 로그인 상태면 `내 공간으로 가기` 하나.
- 첫 문장은 서비스 한 줄 소개(2절). 그 아래 `어떤 분이세요?` 방문자 토글(학생·학부모·선생님)로 본문을 갈아 끼운다.
- 학생: 개인 문제 제공(학년·영역·유형·시험 범위), 오답노트·AI, 약점 진단. 학부모: 자녀 리포트·추이·약점. 선생님: 반 배정·제출 검사·출처 구분.
- 히어로 아래 공통 섹션은 설계 근거(`EvidenceBand`)다. 인용 수치와 출처를 함께 적고, 스코디 자체의 성적 향상 수치는 주장하지 않는다(D-024).
- 목업은 모두 `예시 화면`으로 표기한다.
- `/`는 로그인 상태면 역할 홈, 아니면 웹 `/introduce` · 앱 `/login`으로 보낸다. 앱에는 소개 페이지를 두지 않는다.

### 푸터 문서 `/legal/*`

- `about`(서비스 소개) · `terms`(이용약관) · `privacy`(개인정보처리방침) · `business`(사업자정보). 문안은 `src/features/legal/documents.ts`.
- 약관·개인정보처리방침은 **검토 전 초안**이라고 화면 첫 줄에 밝힌다. 확정본처럼 보이게 하지 않는다.
- 개인정보처리방침 항목 순서는 개인정보 보호법 제30조 제1항을 따른다.
- 사업자정보는 전자상거래법 표시 항목의 틀만 두고 값은 전부 `준비 중`이다. 사업자등록번호·주소를 임의로 채우지 않는다.
- 문서끼리는 `replace`로 이동한다(`push`는 문서 화면이 스택에 쌓인다).

### 학생 앱 — 홈 / 학습 / 기록 / 내 정보

- **홈**: 오늘 해야 하는 학습을 우선순위로. 개인·학원 학습을 한 화면에 두되 출처를 항상 표시한다.
- **학습**: 학년(고1·고2·고3) → 영역(문학·독서·화법과 작문·문법) → 세부 유형 순으로 좁혀 고른다. 학원 학습은 별도 섹션. 개인 구독이 없는 학원 연계 학생에게는 학원 학습을 정상 제공하고, 개인 학습에서는 현재 이용권 상태를 밝힌 안내를 준다.
- **기록**: 완료한 학습(정답률·시간), 오답노트로 공부하기 섹션(카테고리별 진입, 별표 집중 복습, 카드 복습).
- **문항 추천**: 오답노트에 담긴 문항의 세부 유형을 세어 같은 유형의 개인 학습을 추천한다. 결과 화면과 오답노트 화면에 노출하고 추천 이유를 문장으로 함께 보여준다(D-022).
- **내 정보**: 이용권, 연결된 학원, 계정, 설정(테마·공간 전환·로그아웃).

### 학부모 앱 — 홈 / 리포트 / 자녀 / 내 정보

자녀별 종합 리포트(평균 정답률·완료·학습 시간·취약 영역·영역별 정답률·최근 추이·미제출)와 학습별 상세 리포트(문항별 정오, 자녀가 고른 답, 걸린 시간, 오답노트 메모, 재풀이 요청).

### 학원 웹 — 대시보드 / 반·학생 / 학습 배정 / 문제 등록 / 성과 분석 / 학원 관리

대시보드는 장식 차트보다 다음 행동을 우선한다: 미제출 학생, 오늘 마감, 확인이 필요한 학생, 반별 수행률.
반이 100개·학생이 수천 명인 규모에서도 검색과 더보기로 다룰 수 있어야 한다.

### 총괄관리자 `/admin` — 개요 / 학원 / 계정 / 요금제 / 콘텐츠 / 운영 기록

운영자가 확인하는 순서대로 메뉴를 둔다. 모든 화면은 테스트 데이터·추정값임을 화면에 표기한다.

- **개요**: 규모·매출 지표 → 확인이 필요한 것(미제출 배정, 콘텐츠 없는 세부 유형, 오답률 70% 이상 문항) → 최근 등록 콘텐츠 → 자세히 볼 곳 → 지표 정의. 각 지표가 무엇을 세는지 화면에서 밝힌다.
- **학원**: 검색·페이지네이션 목록(좌석·청구액·제출률) → 학원 상세(좌석·청구액·제출률·반별 제출률, 제출률 낮은 반 먼저). 학생 개인 학습 상세는 열지 않는다.
- **계정**: 역할·이용권 필터 + 이름·아이디 검색 + 페이지네이션. 비밀번호는 표시하지 않는다.
- **요금제**: 개인 월정액(학생·학부모), 학원 좌석 단가, 학원 규모 할인율·시작 좌석, 연 결제 할인율·연 결제 비율을 정한다. 바꾸면 MRR·ARR·매출 구성비와 학원별 청구액이 즉시 바뀌고 운영 기록에 남는다.
- **콘텐츠**: 영역 칩(문학·독서·화법과 작문·문법) + 정렬(최근·많이 푼 순·오답률 높은 순) + 검색 + 페이지네이션(10개) → 콘텐츠 상세(학원 배정 풀이 횟수 / 개인 학습 풀이 횟수 / 평균 정답률 / 문항별 오답률 / 어려운 문항 / 배정 학원). 콘텐츠 없는 세부 유형도 함께 보여 준다.
- **운영 기록**: 기본값과 다른 요금 항목, 변경 기록(감사 로그, 분류 필터), 화면의 숫자가 어디서 왔는지, 아직 없는 것.

## 5. 현재 상태

- 프로토타입 사용자 흐름: 완료. 운영 가능한 실제 서비스: 미완료.
- 실제 인증(카카오 OAuth·휴대폰 본인 인증), 영속 데이터베이스, 서버 권한 강제, 결제는 미구현.
- 휴대폰 로그인·가입은 fixture 번호 조회 + 고정 인증번호(`DEMO_PHONE_CODE`) 목업이다. 실제 SMS 발송·재발송·만료·시도 제한은 없다.
- 데이터는 결정적 fixture와 메모리 provider. 전체 새로고침이나 재시작 후 상태 유지를 보장하지 않는다.
- 권한은 클라이언트 provider에서만 강제된다. 실제 데이터 연결 시 서버·DB 정책에서 다시 검증해야 한다.
- Scody AI는 OpenRouter 호출 경계를 가진다. `EXPO_PUBLIC_*` 키는 번들에 노출되므로 운영 전 서버 프록시·인증·rate limit·비용 제한이 필요하다. 키가 없으면 데모 응답임을 화면에 밝힌다.
- 결제는 정책과 UI 경계만 있다. 승인·영수증·갱신·환불·동기화는 미구현.

### 개발 데이터

- 로그인 가능한 테스트 계정 9종(학생 4·학부모 1·학원 2·다역할 1·관리자 1). 각 계정에 합성 전화번호(`010-1000-0001` 형태)가 있고 인증번호는 `000000`이다. 실제 번호가 아니다.
- 규모 확인용 로스터(`src/data/roster.ts`): 반 120개 · 선생 60명 · 학생 3,000명. 결정적으로 생성하며 전화번호·비밀번호가 없어 로그인할 수 없다. 화면에서 실제 재원생처럼 표현하지 않는다.
- 콘텐츠(`src/data/content.ts` + `contentExtra.ts` + `grammarBank.ts`): 모든 세트 10문항 이상, 문법 은행 세트는 20~25문항. 학생 공개 11세트·144문항. 학년·세부 유형 분류는 `src/data/taxonomy.ts`.
