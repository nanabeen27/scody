# UI 일관성 점검 체크리스트

2026-08-05 **출시 전 전수 점검(2차)**. 기준은 `DESIGN.md` §5·§6·§8·§10·§11·§16과 마스터 플랜 D-084·D-091~D-104다.

1차(08-01)는 버튼 모양과 자리를 맞췄고, 2차는 **손으로 누를 수 있는가 · 스크린리더가 읽는가 · 390에서 목적을 잃지 않는가**를 봤다.
화면 56개와 공용 컴포넌트 35개를 전부 읽고, 벤치마킹(Apple HIG 44pt · Material 48dp · WCAG 2.5.5 44px · UX Movement의 모바일 CTA 배치 · Duolingo의 눌림 반응)과 비교했다.

## 점검 항목

| 코드 | 무엇을 보는가 |
|---|---|
| **CTA** | 한 화면에 동시에 뜨는 `primary` 버튼이 1개 이하인가 (§8 R1) |
| **자리** | 화면의 행동이 `ActionBar` 한 줄에 모여 있는가. 세로로 쌓인 낱개 버튼이 없는가 (§8) |
| **폭** | 줄을 채우는 버튼이 그 화면의 목적을 끝내는 것 하나뿐인가 (§8) |
| **어포던스** | 글자만 있는 행동이 없는가. `ghost`에 `leading` 아이콘이 있는가 (§8) |
| **44px** | 목록 안에서 반복되는 행동과 아이콘 버튼의 누름 영역이 44px인가 (§10·D-084) |
| **피드백** | 상태를 바꾸는 행동에 알림이나 화면 변화가 있는가. 대리 보기에서 거짓말하지 않는가 (§8·D-071) |
| **경계** | 경계선 없는 블록끼리 맞닿은 곳에 구분이 있는가 (§6·D-094) |
| **스크롤** | 페이지를 넘겼을 때 보던 자리가 맞는가 (D-095) |
| **터치** | 누르는 것이 44px인가. 예외는 `sm`(32, 섹션 제목 옆)과 `SegmentedControl`(36)뿐인가 (§10·D-097) |
| **접근성** | 상태가 `aria-*`로 DOM에 나오는가. 알림이 스크린리더에 닿는가. 포커스 링이 보이는가 (§11·D-096·D-100) |
| **표** | 390에서 열이 사라지지 않는가 (§10·D-098) |

`—` 는 해당 없음. `⚠️` 는 남긴 것.

## 만든 것 · 지운 것

**만든 것**: `EmptyState`(56곳 통합) · `ConfirmStep`(4곳) · `BarRow` · `SourceValue`(축자 복사 5곳) · `Disclosure` · `LiveRegion` · `useColumn` · `styles.ts`(`row`·`inset`·`a11y`) · `touch`·`spacing.xxs/xs2`·`columnBreakpoints`·`shadow`·`FOCUS_CSS` 토큰 · `AppText`의 `weight`/`danger`/`success`/`numeric`.

**지운 것**: `QueueToggle.tsx`(같은 컴포넌트를 세 번 복사한 것 → `IconButton`으로 흡수) · `styles.tap`·`undoBtn` 6개 선언 13개 호출부 · `Table`의 `minWidth` prop과 17개 호출부 · `Table`의 지역 폭 실측.

**넣지 않은 것**: `Cluster`/`Inline`(121곳 JSX를 고쳐 객체 하나를 아끼는 거래 — 출시 직전 최악의 위험/이득비) · `FilterBar`(화면마다 재료가 달라 props 가방이 된다) · `Checkbox`(`IconButton`으로 흡수) · 반응형 타이포(시각 위험이 가장 크고 모든 화면 제목이 움직인다).
